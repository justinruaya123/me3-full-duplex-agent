# Pi-default full-duplex implementation plan

**Goal:** Implement the November 4 specification on the existing prototype.
**Architecture:** Keep the controller independent of harnesses. A long-lived
runtime owns durable jobs; voice sessions own perception and playback only.
Foreground HTTP inference is separate from a local, tool-disabled Pi worker.
Website generation returns structured files to a host-enforced static build
boundary rather than giving generated code arbitrary host shell access.
**Tech stack:** Python 3.13, asyncio/SQLite, Pi 0.84.2, optional Pipecat/MLX/Kokoro.
**Spec:** `docs/ME3_SPEC_2026-11-04.md`.

The user explicitly requested implementation and continuation, without a new
proposal or confirmation cycle. Execute inline using TDD and coherent commits.
Only one attachment is accessible; the six stage names in the request are the

## Stages and regression gates

1. Configuration/runtime separation (`configuration.py`, `foreground.py`,
   `runtime.py`, `harnesses.py`): Pi default, distinct exact model IDs, explicit
   endpoint/auth settings, and closing a voice session leaves a blocked real
   Supervisor job running and able to complete. No credential values in reports.
2. Incremental speech/playback (`incremental.py`, `duplex.py`, voice bridge):
   timestamped rolling ASR revisions/commits; provisional text never authorizes;
   cancellable clause streaming, stale playback receipts, pause/resume buffers.
3. Ownership/turn handling (`ownership.py`, session ingress): wake creates only
   a candidate; deliberate enrollment; owner/addressee/overlap checks; session
   epochs and monotonic transcript revisions; physical mute bypasses inference.
4. Pi website jobs (`pi_worker.py`, `website.py`): installed RPC checks, explicit
   exact model selection, persistent job sessions, settled/error semantics,
   scoped file writes and trusted build/syntax checks; no generated shell calls.
5. Results/context (`duplex.py`, runtime): owner-filtered notices and job APIs,
   stale revision rejection, deduplication, revise/cancel/results, explicit focus
   return, deferred grouped notices, approved loopback preview URLs.
6. Benchmark/deployment (`doctor.py`, setup docs/evidence): reproducible local
   installation, dependency/API smoke, actual Pi RPC without assumed credentials,
   separate simulator/provider/acoustic/Pi receipts; unchanged external scorer.

Each stage: write regressions, record RED, implement, run complete suite, commit.
Use a final independent whole-branch review as required by executing-plans.

## Review focus

- Late ASR and playback lifecycle events from an earlier session or revision.
- Worker cancellation-resistant results or malformed generated file bundles.
- Failed or absent providers, permission errors, and blocked model catalogs.
- New owner receiving earlier-owner notices or authorizing ambiguous references.
- Transport disconnect, mute and runtime restart without replaying side effects.
