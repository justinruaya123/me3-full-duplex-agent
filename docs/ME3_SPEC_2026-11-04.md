# ME3 — Full-Duplex Agent
### Implementation specification · v1.0 draft · 4 November 2026

**Goal:** GPT-Live-style continuous conversation, independent delegated work, and natural return of results—not replication of OpenAI’s internal model or an unmeasured parity claim.[1]

**Scope:** macOS validation; Raspberry Pi-ready deployment. Your Pi.dev selection supersedes the worksheet’s older “Hermes first” default; retain Hermes compatibility. Preserve ME2. Formal ME3 rubric compliance remains unverified.

## 1. Selected architecture

| Responsibility | Selection |
|---|---|
| Runtime | Pipecat on macOS initially; the same controller, job store, harness and tools later run on Pi 4/4 GB/64-bit Linux. Only inference is offloaded; MLX stays outside the portable runtime. |
| Speech server | Separate M2 service: Whisper **large-v3-turbo through MLX** and Kokoro. Accessible locally or from the Pi over an authenticated LAN connection. |
| Foreground conversation | **One selected profile:** local Nemotron MLX **or** API-hosted Qwen 3.8 with reasoning disabled. Do not chain both. |
| Delegated work | Persistent **Pi.dev** worker sessions using the requested **Sol** model through a supported ChatGPT sign-in. Keep a Hermes adapter behind the same interface. |
| Demonstration | Build a website while continuing conversation; revise it, return verified results, and launch its local preview on request. |

**Two LLM roles; no third orchestration LLM.** Speech/turn/speaker models are separate. Reserve audio/foreground capacity against worker and build contention.

**Deployment settings remaining:** exact model IDs, chat profile/endpoint and wake phrase. “OpenAPI” means OpenAI-compatible here; the provider remains unspecified. Verify non-reasoning mode and ChatGPT access through actual requests. Never silently switch models or billing.[11]

```text
Microphone → echo cancellation → wake/session + speaker verification
                                      │
                           VAD + revisable ASR + turn cues
                                      │
                         Harness-neutral controller
                         ├─ foreground LLM ───────────────┐
                         └─ durable jobs → Pi / Hermes    │
                                            ↓             │
                                  verified result queue ──┤
                                                          ↓
                                  single speech scheduler → Kokoro → speaker
                                                          ↑
                                          playback receipts / interruption
```

Capture continues during playback. ASR, verification and turn analysis run concurrently. Workers never speak directly.

## 2. Reuse Pipecat; separate three decisions

| Question | Implementation direction |
|---|---|
| **Has the user finished?** | Silero VAD + `LocalSmartTurnAnalyzerV3`, with transcript readiness and dialogue context. Silence alone is insufficient.[3] |
| **Should the assistant yield?** | Owner-aware interruption strategy. Pipecat’s `KrispVivaIPUserTurnStartStrategy` distinguishes interruptions from acknowledgments; qualify SDK/platform access. Contextual-ASR fallback is a labelled baseline, not equivalent performance.[4] |
| **Should the assistant acknowledge?** | Gate neutral, cached Kokoro clips at pauses inside unfinished turns. Reuse the community `pipecat-backchannel` approach without unnecessarily duplicating VAD/turn inference.[5] |

LiveKit’s alternative uses Cloud inference and aligned transcripts; do not add a second framework.[6] Turn detection and noise suppression do not establish speaker identity.

**Streaming:** require timestamped ASR partials, revisions and commits. Pipecat’s Whisper service is offline/segment-based; add and measure rolling-window/stable-prefix reconciliation.[7] Stream LLM clauses to cancellable TTS. Tag transcripts/jobs/audio with session/revision IDs; reject stale output. Specify resampling: benchmark input is 16 kHz mono.

## 3. Ownership and interaction

**Flow:** wake → establish owner → converse → delegate → continue/change topic → offer result → accept/defer/return → end.

Wake opens an **ownership candidate**, not a verified identity. Compare speech with a session-local speaker reference.[9] Short/noisy wake audio requires deliberate enrollment—not blindly adopting the next speaker. Uncertain/mixed speech cannot authorize answers or tools.

Only verified owner speech updates context or controls jobs; another wake cannot steal the session. Check whether the owner addresses the assistant, too. End ownership explicitly or after configured inactivity. Physical mute and local stop controls remain available through inference failures. VoiceID is not sensitive-action authentication.

| Situation | Required behavior |
|---|---|
| Hesitation, unfinished sentence, dictation | Hold the turn. Do not treat an ASR delay/timeout as a completed request; clarify after a genuine gap. |
| “Mm-hmm,” “yes,” “yes, but…” | Preserve acknowledgment without stopping the explanation; treat an answer to a pending question as an answer. Retain corrections and late transcripts at response boundaries.[6] |
| Uncertain names/numbers or transcript gaps | Ask before acting; never execute a convenient fragment. |
| Agent backchannel | Brief, neutral, interruptible and rate-limited; no agreement or success claim. Suppress during names/numbers/code dictation and approval questions. |
| Genuine interruption / false alarm | Preserve onset audio. Pause playback provisionally without destructive cancellation; resume false alarms from unplayed audio. Confirmed interruptions flush obsolete output. |
| Echo, TV, bystander, overlapping voices | Apply playback-reference echo cancellation plus owner/addressee checks. Do not answer or execute from unverified fragments. |
| “Stop talking,” “cancel that,” repeated request | Separate speech stop, foreground generation cancellation and job cancellation. Clarify ambiguous scope; deduplicate task submissions and actions. |
| Completion while busy / several completions | Wait until the owner’s turn and pending ASR clear. Group/retry notices. Return relevant results in context; otherwise offer “By the way, your site is ready.” Never seize focus. |
| “Go back,” “show it,” new topic | Track topic and job separately; resolve references or ask. Preserve the earlier thread. Returning a result does not automatically replace it. |
| End, disconnect, restart or failure | End voice without cancelling jobs. Reconcile interrupted jobs after restart; never blindly replay actions. Require renewed ownership before notices. Report failures/unknown outcomes, never mock success. |

## 4. Agent workflow and boundaries

**Delegate:** clarify → persist request/context and ID → acknowledge → plan/build/test → verify → queue notice. Simple conversation stays foreground. Only owner-verified, committed turns authorize job submission, revision or approval.

Expose `submit/status/revise/cancel/result` and completion events. Jobs carry owner/session, workspace, revision and verification receipt. Start with one worker and a bounded queue. Pi RPC acceptance is not completion: await settlement, then verify errors/artifacts.[8]

**Website:** require files, passing build/tests and a responsive preview. “Launch it” starts an approved local preview and returns its validated URL—not public deployment. Report build failures and already-applied changes after cancellation; suppress superseded results.

**Permissions:** authorize scoped editing/build/testing, not unrestricted host access. Enforce permissions outside prompts; isolate credentials. Public deployment, destructive/out-of-scope changes and external commitments require approval. A directory is not a sandbox; tool output is untrusted data.

**Context/privacy:** retain confirmed facts, corrections, task references and played speech; label uncertain delivery. Bound history/queues/deadlines; preserve approvals across compaction. Mute clears capture; recordings require opt-in; erase voice references on close. Never deliver previous-owner results to a new owner.

## 5. Acceptance: Mac first, Pi separately

Keep the scorer unchanged.[2] Pin code/models/data/judge/seed; freeze thresholds on development recordings. Reset session/job state—not merely silence. Never expose scenario labels to the controller.

**Two declared profiles:** course duplex tests use identical preactivation and globally bypass ownership when clips lack consistent speakers. Separate end-to-end ownership tests keep wake/verification enabled. Never mix scores or claim ownership success from bypassed tests.

| Gate | Required evidence |
|---|---|
| Duplex behavior | Pause/missed/false turns; interruption relevance; Respond/Resume/Uncertain/Unknown; stop/response latency and voice changes. Include failures, counts and uncertainty. |
| Proposed latency targets | **p95 interruption onset → actual playback stop ≤250 ms; p95 completed conversational turn → substantive audio ≤1 s.** Include detection/network/buffering; fillers do not count. Report task completion separately. |
| Ownership | Unseen speakers, short answers, owner addressing others, competing speakers, replay and simultaneous speech. Report owner rejection, wrong-owner acceptance and wake false activations. |
| Agent/context correctness | Website built while conversing; correction/cancellation; multiple jobs; deferred notices; “go back”; no stale actions, duplicate execution or unsolicited focus changes.[10] |
| Deployment | Idle versus busy-worker/M2-contention runs; model/network failure, restart and mute. Physical speakerphone echo/double-talk, accents, and 30-minute soak on each target: CPU, peak memory, temperature where available and audio dropouts. |

Targets are not course thresholds. Compare speech-to-speech references on the same rig. Mac/headphone results cannot qualify Pi/speakerphone performance.

**Delivery order:** Mac speech → ownership/turns → Pi.dev delegation/return → benchmark → physical Pi qualification. Preserve the prototype baseline. Source inspection is not runtime validation.
